# sustag future-work research — split run

The research workflow ("highest-value future work for the Iowa nitrate virtual-sensor
problem") was split in two so the expensive synthesis stage could be deferred.

**Part 1 — search / fetch / verify: done, banked here.**
**Part 2 — synthesis: run it when usage allows, using the files in this directory.**

## Why it was split

The original run died twice: once on a monthly spend limit, once on a silent runtime
crash. The workflow's `journal.jsonl` caches every completed agent, so restarts replay
finished work for free — but the synthesis stage is by far the most token-expensive part
and, because the pipeline has no barrier between stages, it fires per-angle as soon as
that angle finishes verifying. The script was therefore edited to stop after
verification (two early `return`s; the original synthesis calls remain in the file but
unreachable).

## Files

| File | What it is |
|---|---|
| `sustag-future-work-wf_0dd2bcea-c63.js` | The (edited, verification-only) workflow script. `PROJECT` and `RULES` are read out of this file by the assembler. |
| `journal-snapshot.jsonl` | Agent-result cache from the runs. Note: verdict records carry no claim text, so this file **cannot** reconstruct claim↔verdict mapping on its own. Kept for provenance and raw source/claim material. |
| `build_synthesis_input.py` | Assembles `synthesis-input.json` from the script + the verification run's return value. |
| `synthesize.js` | Synthesis-only workflow: 8 angle syntheses in parallel, then the cross-angle ranking. Schemas inlined verbatim from the original. |
| `banked-verified-claims.json` | 37 claims from the original run, each verified by the full 3-lens panel (30 survived, 7 refuted). Recovered by joining agent transcripts (which contain the claim text) to journal verdicts (which do not) on `agentId`. |
| `synthesis-input.json` | Generated by the assembler. This is the args payload for `synthesize.js`. |

## Current configuration: verification SKIPPED, three-tier evidence

Verification was cut after 37 claims. Measured cost is **~$2.83 per verifier agent**
(each runs an open-ended browsing loop; ~734k cache-read tokens apiece), so verifying the
remaining 489 would cost **~$1,300**. Feeding them to synthesis as unverified context
costs **~$3 total and zero extra agent calls**, so that is what the current setup does.

Evidence tiers now reaching the report:

| Tier | Count | Status | Allowed use |
|---|---|---|---|
| 1 | 30 | 3-lens verified, survived | Load-bearing |
| 1 | 7 | 3-lens verified, refuted | Passed through as corrections |
| 3 | 489 | **Unverified** | Coverage and leads only — never the warrant for a number or a core argument |

`A5-network-topology` and `A8-target-methodology` have **zero** verified claims and rest
entirely on tier 3. The synthesis prompt requires the final report to say so.

## How to finish it (synthesis only — ~9 agent calls, ~$15)

The input is already built. `synthesis-input.json` was assembled directly from the on-disk
cache by `assemble_from_cache.py` — no workflow re-run, no LLM cost. Just run:

```
Workflow({scriptPath: "notes/research-cache/synthesize.js",
          args: <parsed contents of synthesis-input.json>})
```

Pass `args` as an actual JSON value, not a JSON-encoded string. If the cache changes,
regenerate first with `python3 notes/research-cache/assemble_from_cache.py`.

## Restarting verification later, usage permitting

Nothing has been discarded — all 526 claims, their sources, and the 111 banked votes are
in `synthesis-input.json` and `journal-snapshot.jsonl`. To verify more:

1. **Decide how many.** Budget ≈ **$2.83 × (number of claims × votes per claim)**. A
   useful middle path is 1 vote on the ~100 claims that actually underpin the ranked
   recommendations in the finished report, rather than all 489 — read the report first and
   verify what it leans on. That is ~$280 instead of ~$1,300.

2. **Restore verification in the workflow script.** In
   `sustag-future-work-wf_0dd2bcea-c63.js`, stage 3 currently has an early
   `return` that passes claims through unverified, and stage 4 plus the cross-angle call
   have early `return`s that stop the run before synthesis. Delete whichever you want to
   re-enable. The original 3-vote code is intact and unreachable below them; the lens list
   was narrowed to `['primary-source']` and the majority test to `kills < 1` for 1-vote
   mode. `claims.slice(0, 7)` caps how many claims per angle are verified — raise it.

3. **Or verify standalone, which is cheaper and simpler.** The workflow's resume has twice
   re-run extraction instead of replaying it, which costs more than the verification
   itself. Prefer spawning verifier agents directly over claims read from
   `synthesis-input.json`, using the REFUTE prompt in the script as the template.

4. **Fold results back in.** Verdicts land in the journal without claim text; recover the
   mapping by joining each agent's transcript (line 0 holds its prompt, claim included) to
   the journal verdict on `agentId` — that is how `banked-verified-claims.json` was built.
   Append to that file and re-run `assemble_from_cache.py`, which promotes newly verified
   claims out of tier 3 automatically.

## Caveat to carry into the final report

Verification ran at **3 votes per claim** for the first 37 claims and **1 vote**
(`primary-source` lens) thereafter, switched mid-run to conserve usage. The 3-vote claims
are carried separately in `banked-verified-claims.json` and the synthesis prompt tells the
final agent to prefer them where the two pools conflict. So the evidence base is not
uniform in strength — the final report should not read as though it were.

The verify stage used `claims.slice(0, 7)` — only the **first 7 claims per angle** were
ever verified, out of ~349 extracted. That is a hard slice in extraction order, not a
quality ranking. The synthesis prompt in `synthesize.js` instructs the final agent to
state this in its `bottomLine`, but it is worth remembering when reading the output:
coverage is partial by construction.

One angle (`A5-network-topology`) lost its original search agent to a connection error
and was re-researched from scratch in a later run.
